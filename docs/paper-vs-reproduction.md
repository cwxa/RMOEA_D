# 论文对照：Li et al. (2022) ESWA 203:117380 与本项目复现结果

> 对照对象：**R. Li, et al. "A reinforcement learning based RMOEA/D for bi-objective fuzzy
> flexible job shop scheduling." Expert Systems With Applications 203 (2022) 117380.**
> 所有论文数值均直接从 PDF 正文表格转录，未做任何加工。
>
> **一句话结论**：我们的复现是忠实的；复现得到的 null 结果与**论文自己公开的逐实例数字**
> 一致，而与论文的文字结论不一致。论文声称 Q-PAS 有效所依据的证据是
> **整梯 Friedman 排名**（p=1.5e-4）与**定性曲线**，**没有对 Q-PAS 单独做任何配对检验**；
> 而它自己 Table 5 里 Q-PAS 那一步的逐实例效应量只有 **+0.56%**（全 23 实例 15/23，精确符号
> 检验 p=0.21）、FMk 上 **+0.81%**（7/10，p=0.34）——**都不显著**。

**三处必须声明的结构性差异**

1. **阶梯的切分点不同。** 论文的阶梯是「逐级累加」：D3 已经有**随机选择的 VNS**，D4 只是在其上

2. **论文的 D3「随机 VNS」在本项目原先缺失。** 已补：`src/rmoea_d/core/rvns.py` 新增 `mode="random"`

3. **论文的 D1 / D2 在本项目原先无法构造。** `RMOEAD` 把 MIX3 初始化与 Elite archive
   写死在代码里，所以"纯 MOEA/D"（D1）和"+MIX3"（D2）两个中间级根本没有对应的配置。
   已补两个开关 `enable_mix3` / `enable_elite`（默认 `True`，不改变既有行为），
   现在 §5.4 的六级阶梯可以在同一份代码上逐级打开。实验台见
   `scripts/ablation_ladder.py`，分析见 `scripts/ablation_ladder_analysis.py`，
   诊断结论见 `docs/ablation-qpas-rvns-diagnosis.md` §9。
   **已按全量跑完**：8 臂 × 10 实例 × 30 seeds = 2400 runs，
   整梯 Friedman p=6.74e-07 \*\*\*，D1→RMOEA/D 排名增益 +3.80（论文 +2.22）。

## 2. 论文自己的数据说了什么

### 2.1 Table 5 逐步骤效应量（把论文的表当成复现结果来审计）

论文 Table 5 给出 23 个实例（D1–D5、R1–R8、FMk01–10）上 6 个变体的平均 HV（各 30 次运行），
但**只给均值、不给每次运行的值**，所以只能做实例级符号检验（比配对 Wilcoxon 弱，已标注）。

| 阶梯步骤 | 排名增益 | 平均 ΔHV | 相对 | 改善实例 | 精确符号检验 |
|---|---|---|---|---|---|
| MIX3 初始化 | +0.22 | +0.002268 | **+5.06%** | 17/23 | **p=0.035 \*** |
| 随机选择 VNS | +0.78 | +0.000744 | **+1.29%** | 17/23 | **p=0.035 \*** |
| **Q-PAS** | **+0.52** | +0.000242 | **+0.56%** | **15/23** | **p=0.210 n.s.** |
| Elite archive | +0.17 | −0.000051 | −0.19% | 14/23 | p=0.405 n.s. |
| **RVNS**（替代随机 VNS） | **+0.52** | +0.000088 | **+0.15%** | **13/23** | **p=0.678 n.s.** |

> 符号约定：**排名增益 = rank(上一级) − rank(这一级)，>0 = 排名变好**（名次数字下降）。
> ΔHV 越大越好，>0 即该组件正贡献。

**这些步骤的显著性很弱**（唯一两个达 * 的是 MIX3 与随机 VNS，且用的是比配对
Wilcoxon 弱的实例级符号检验），**论文从未对任何单个组件做过配对检验**。

只看 FMk01–FMk10（本项目的基准）：

| 步骤 | 平均 ΔHV | 相对 | 改善实例 | 符号检验 |
|---|---|---|---|---|
| MIX3 初始化 | — | −1.13% | 5/10 | 1.000 n.s. |
| 随机选择 VNS | — | +0.41% | 6/10 | 0.754 n.s. |
| **Q-PAS** | +0.000335 | **+0.81%** | **7/10** | **0.344 n.s.** |
| Elite archive | — | −0.42% | 5/10 | 1.000 n.s. |
| RVNS | — | +0.47% | 7/10 | 0.344 n.s. |

Q-PAS 在 FMk 上的逐实例增量（这也是最容易写进论文的形式）：

```
FMk01:+0.00068  FMk02:+0.00091  FMk03:-0.00049  FMk04:+0.00087  FMk05:-0.00002
FMk06:+0.00071  FMk07:-0.00032  FMk08:+0.00047  FMk09:+0.00047  FMk10:+0.00005
```

### 2.2 「排名增益」与「效应量」严重脱节

论文 §5.4 的原话是 *"Friedman rank is shown in Table 4, each part improves the result
against the last one. That proves the effectiveness of each part."*
但 Table 4 的排名增益与 Table 5 的效应量对不上：

- **Q-PAS 与 RVNS 的排名增益并列最大（各 0.52 名）**，而这两人的逐实例效应量是全场
  **最小**的（+0.56%、+0.15%），符号检验都是 n.s.；
- 排名增益**最小**的是 MIX3 初始化（0.22 名），而它的效应量是全场**最大**的（+5.06%，p=0.035\*）。

原因是口径不同：Friedman 比较的是**同一实例内 6 个变体之间的相对名次**。当 6 个变体几乎
打平时，一个稳定高出 0.5% 的变体就能在多数实例上排到更前，从而累积出很大的"排名增益"。
**排名增益度量的是"稳定地略好"，不是"好多少"。**

> **因此不能照抄论文的推断方式。** 论文从未对任何单个组件做配对检验——它是把 6 个变体
> 一起做一次 Friedman（p=0.00015），再按排名顺序把功劳分配下去。

### 2.3 Q-PAS 的"有效性证明"是定性的，不是统计的

论文 §5.3 *"Discussion about Q-PAS"* 声明的依据只有两样：

1. **Fig. 8**：一次运行（D1 实例）的 CV/DV 变化曲线，观察到 DV 的"先降后升"周期；
2. **Table 3**：200 代后的 Q-table。

两者都不是统计检验。而且这两条证据本身也有可质疑处：

**(a) Table 3 暴露的是"早期幸运锁定"，不是"每状态最优策略"。**

| 状态 | T=5 | T=10 | T=15 | T=20 | argmax |
|---|---|---|---|---|---|
| State1 (ΔCV>0, ΔDV>0) | 0 | 1.798693 | 0 | 6.743954 | T=20 |
| State2 (ΔCV>0, ΔDV≤0) | 0 | 0.323268 | 0 | 5.271637 | T=20 |
| State3 (ΔCV≤0, ΔDV>0) | 4.539988 | 0.766909 | 0 | 0 | T=5 |
| State4 (ΔCV≤0, ΔDV≤0) | 2.847096 | 2.283770 | 2.911486 | 1.152641 | T=15 |

- 16 个格子里 **6 个在 200 代后仍精确为 0（38%）**——意味着某些 (状态, T) 组合**整场从未被
  奖励过一次**。以 ε=0.8（80% 利用）的动力学看，一旦某个臂先撞上奖励，argmax 就会反复拉它，
  其余臂停在 0。**这张表记录的是"第一个成功的臂"，不是"每状态的正确 T"。**
- 按 γ=0.6、奖励上限 10 反推，Q 的理论天花板是 `10/(1−0.6) = 25.0`；表中最大项 6.743954
  对应经验成功率仅 **≈0.27**。奖励信号本身极稀疏。
- **与论文自己的叙事矛盾**：§5.3 说"若 CV 与 DV 都难增，T=5 或 10 有助于提升 DV"，
  而 State4（正是"两者都难增"）的 argmax 是 **T=15**（2.911 > T=5 的 2.847）。

**(b) 论文调参把 ε 推向最"利用"的一端。** DOE 的 4 个水平是 ε ∈ {0.95, 0.90, 0.85, 0.80}，
选出的最优是**最小的 0.80**（= 利用最强）。这提示"更多利用更好"，而利用最强的极端就是
纯贪婪；与 Table 3 的锁定现象一致。

**(c) 奖励目标与优化目标错位。** 论文 Eq (15) 定义的 DV 是
`Σ|d_i − d̄| / ((N−1)d̄)`——注意它衡量的是间距的**非均匀度**：完全等距时为 0。
论文正文却写 *"The bigger DV is the better diversity is"*，并奖励 ΔDV>0。
更关键的是 DV 对**前沿整体铺开的宽度不敏感**（对 d 整体缩放不变），所以它**看不见**
论文所声称的"提升前沿覆盖广度"这件事。

> 本项目按论文原样实现（`reward_mode="dv"` 为默认），因此这是**论文层面的设计问题**，
> 不是复现错误。

### 2.4 HV 归一化口径跨表不一致

论文 §5 只说 *"all **x** should be normalized in same reference point"*，
**未说明 f1min / f1max 从何而来**。同一算法同一实例在两张表里给出了不同的 HV：

| 实例 | Table 5（变体对比） | Table 7（算法对比） | 差 |
|---|---|---|---|
| FMk01 | 0.057207 | 0.073803 | +0.016596 |
| FMk05 | 0.048468 | 0.062563 | +0.014095 |
| FMk06 | 0.044598 | 0.132173 | +0.087575 |
| FMk09 | 0.042508 | 0.092580 | +0.050072 |
| FMk10 | 0.063283 | 0.172348 | **+0.109065** |

归一化盒显然是**按实验重新设定**的。后果：

1. 论文的绝对 HV **不能与本项目的复现数值直接比较**（我们的量级是 0.8 左右，论文是 0.05 左右）；
   只有**表内相对增量**有信息量。
2. 若 f1min / f1max 是**逐前沿**取的，那正是本项目查出的那个会抹平算法差异的口径缺陷
   （诊断文档 §1.1：修掉后 mk01 的 Friedman p 从 0.668 变成 0.0046）。
   **这一点值得在论文里明确写清归一化盒的来源。**

### 2.5 论文 §5.4 那句断言的逐实例查证

论文 §5.4 原文：*"each part improves the result against the last one."*
这是一个**逐实例**的断言。把 Table 5 的 23 个实例按阶梯顺序逐一查单调性
（HV 越大越好，要求相邻每级**严格递增**）：

**只有 2 个实例（R7、FMk10）逐级单调；其余 21 个都有倒退。**

| 倒退级 | 出现的实例数 |
|---|---|
| `RMOEA/D5 -> RMOEA/D`（换成 RVNS） | **8** |
| `RMOEA/D4 -> RMOEA/D5`（加 Elite archive） | 7 |
| `RMOEA/D3 -> RMOEA/D4`（加 Q-PAS） | 5 |
| `RMOEA/D1 -> RMOEA/D2`（加 MIX3） | 5 |
| `RMOEA/D2 -> RMOEA/D3`（加随机 VNS） | 3 |

最刺眼的两处：**FMk01 的 D1（0.058504）反而高于 D2（0.055246）**；
**FMk08 的 D1 > D2 > D3 连续三级倒退**。

→ **这句话真正成立的层次是「Friedman 平均排名逐级改善」**
（4.6087 → 4.3913 → 3.6087 → 3.0870 → 2.9130 → 2.3913，确实是单调的）。
两者不矛盾，但**不能把平均排名的单调性当作每个实例的单调性**——
这是审稿人最容易挑的一点，建议论文里改写为
「Friedman 平均排名逐级改善」并补上单组件的配对检验。

## 3. 复现结果：组件分解（Mk10，n=30，同强度配对）

补齐 `RandVNS` / `RVNSonly` 两臂后，把论文阶梯缺失的那一环补上：

**Mk10，Np=100，G=200，n=30 seeds/臂，28 臂 / 840 runs，
HV 按参考集归一化（所有臂所有 run 的前沿并集，ref=(1.02,1.02)）**

| 同强度对照 | ΔHV | 胜负 | 相对 | Wilcoxon p |
|---|---|---|---|---|
| 加上局部搜索本身（算子随机选），`ls_trials=1` | +0.04671 | 24/30 | **+5.68%** | 1.8e-05 \*\*\* |
| **RL 引导选算子 替代 随机选算子**，`ls_trials=1` | **−0.00219** | 13/30 | **−0.25%** | **0.529 n.s.** |
| 在已有局部搜索上再加 Q-PAS，`ls_trials=1` | +0.00482 | 19/30 | +0.56% | 0.280 n.s. |
| Q-PAS 单独（无局部搜索） | +0.01281 | 17/30 | +1.56% | 0.271 n.s. |
| 加上局部搜索本身（算子随机选），`ls_trials=3` | +0.06852 | 28/30 | **+8.32%** | 9.3e-09 \*\*\* |
| 邻域尝试 1 → 3 次 | +0.04058 | 24/30 | **+4.68%** | 3.5e-05 \*\*\* |
| **RL 引导选算子 替代 随机选算子**，`ls_trials=3` | **+0.01658** | 21/30 | **+1.86%** | **0.0449 \*** |
| 在已有局部搜索上再加 Q-PAS，`ls_trials=3` | −0.01354 | 14/30 | −1.49% | 0.129 n.s. |

**与论文的两处关键吻合**

1. **Q-PAS**：论文 +0.56%（p=0.21）/ FMk +0.81%（p=0.34）↔ 本项目 +1.56% ~ +0.56%（p≥0.27）。
   **两个独立实验、四种语境，Q-PAS 全部 n.s.，且符号在大局部搜索下转负。**
2. **RL 引导选算子**：论文 +0.15%（p=0.68）↔ 本项目 `ls_trials=1` 下 −0.25%（p=0.53）。
   **论文阶梯里 RVNS 那一步之所以微弱，根因是 `ls_trials=1` 让算子选择没有发力空间**——
   把尝试次数提到 3，同一对照立刻变成 **+1.86%（p=0.045\*）**。

**贡献排序（Mk10）**

| 组件 | 相对增益 | 显著性 |
|---|---|---|
| 加上局部搜索本身 | +5.68% | \*\*\* |
| 每代邻域尝试 1 → 3 次 | +4.68% | \*\*\* |
| RL 引导选算子（需 `ls_trials ≥ 3`） | +1.86% | \* |
| Q-PAS 单独 | +1.56% | n.s. |
| Q-PAS 叠加到局部搜索上 | +0.56%（t=1）/ −1.49%（t=3） | n.s. |

最高配置是 **`fixed_T=10 + RVNS(ls_trials=3)` = 0.90819**，超过全部 `Full`（Q-PAS + RVNS）配置
（0.872~0.876，均含 `ls_trials=1`）。即：**加 Q-PAS 不如把邻域搜得更狠。**

## 4. 论文里可以怎么写（建议）

**可以主张（证据扎实）**

- **按论文 §5.4 的完整六级阶梯，MIX3 初始化是最大的单一组件（+14.46%，10/10 实例，
  p=0.00195\*\*），其次是局部搜索（+3.72%，10/10，p=0.00195\*\*）。**
  （注意：§3 的 Mk10 组件分解因为 baseline 已含 MIX3 而**看不到**这一环。）
- **Elite archive 有真实但微小的正效应**（+0.28%，10/10 实例，2×2 主效应 293/300，
  p=8.5e-50\*\*\*）——统计上极稳，但效应量小到没有实际意义，报的时候两个数都要给。
- 局部搜索对 RMOEA/D 贡献显著，且**邻域尝试次数是关键设计变量**——论文 Algorithm 4 的
  单步 first-improvement 设置削弱了 RVNS 自身的 RL 机制；提到 `ls_trials=3` 后
  RL 引导选算子才转为显著的 +1.86%（p=0.045\*）。
- 用**逐实例配对检验**报告消融（论文只做了整梯 Friedman 排名），并给出效应量而非仅排名。

**不要主张（会被审稿人抓住）**

- ❌ **不要写「每一级都优于上一级」。** 论文自己的 Table 5 在 23 个实例里只有 2 个
  逐级单调（见 §2.5）。改正为「Friedman 平均排名逐级改善」。
- ❌ **不要声称 RVNS 的 RL 选算子有正贡献。** 阶梯里 D5→RMOEA/D 这一步是**唯一的倒退级**
  （−0.02%，6/10 实例 D5 更好，p=0.92）；论文自身数据在同一级也倒退（8/23，全场最高频）。
- ❌ 不要声称 Q-PAS 有显著贡献。五个独立语境均 n.s.，且在强局部搜索下为负；
  阶梯里其 T 使用分布约 25%/档，与均匀随机无差别（见诊断文档 §9.3(d)）。
  可写成："Q-PAS 在本基准上未产生可检测的增益；其作用依赖于邻域大小 T 是否为有效杠杆
  （Mk01 上 T 是弱杠杆，Friedman p=0.15）。"
- ❌ 不要用"前沿延展度 EXT"为 Q-PAS 辩护。Mk01 上 EXT 看起来 +13.3%（p=0.017），
  但拆开两端后是**假象**：好端无差异（p=0.68），增量几乎全部来自差端显著变差（p=0.0137）。
- ❌ 不要把 `MOEADBaseline` 当"独立的标准 MOEA/D 实现"来比（它继承了 MIX3、模糊解码、
  精英存档等，只是剥掉了两个 RL 组件；本项目里 `moea_d` 与 `T10_fixed` 的 HV **逐位相同**）。
  建议改称 "RMOEA/D w/o RL components"。
- ⚠️ 报 HV 时必须**明确归一化盒的来源**，并保证跨表一致（见 §2.4）。

**未来工作方向（2026-09-17 更正）**

> ⚠️ 本节早前两条例目已作废：**per-seed oracle 不能当目标**（是选择偏差——观测

> **动作空间天花板被高估**（T=50 vs 空间内最优 T=15 仅 +0.00256，即 +0.31%，
> p=0.777 n.s.）。见 `docs/ablation-qpas-rvns-diagnosis.md` §7.4。

- **不建议**继续在"用 RL 选 T"上投入。三条独立证据：
  ① 动作空间天花板只有 **+0.31%，n.s.**；
  ② Q-PAS 最好配置已达到其动作空间内的最优常量 T（**−0.00144, p=0.935 n.s.**）
  ——**瓶颈不在学习**；
  ③ 唯一学到偏好的配置（`QPAS2_opt_hv`，T=50 占 38.3%）HV 反而更低。
- **搜索预算的分配也已检验完毕，同样是负结果**（2026-09-17 补，避免有人再走一遍）：
  ABA 把总算力**构造性固定**为「每代每解均值 2」，只改变"加码名额发给谁"，
  四种策略（随机／状态／学习／反极性）在 Mk10（开发）+ Mk07/Mk09（确认）上
  **都跑不过统一上限 2 的等算力基准**，也没能显著胜过随机发放的异质性对照
  （留出集 Mk07 上"知情"臂方向一致地 +1.2%，但 p=0.052–0.135 过不了线，
  Mk09 上只剩 +0.2–0.5%）。见 `docs/aba-budget-allocation.md` §6。
  → 结论：**T 维度没有空间，预算分配维度同样没有；RL 组件在这两个"选什么"的动作上都没有空间。**
- **唯一还没被证伪的改进方向：初始化**——MIX3 是全场最大单一组件
  （**+14.46%\*\***，10/10 实例），却**从未做过变体扫描**。若要继续做改进版，
  应从这里下手（且必须另立标签，见 §2.4/C4）。
- **算力公平性已补齐，结果是"这三个数都不是算法效应"**（`logs/_eqc_compare.txt`）：

  | 论文口径的结论 | 算力对照 | 等算力下 |
  |---|---|---|
  | `T50` vs `T10` = +0.0168\* | `T10` 补足代数（`T10_G440`） | **反超 T50 +0.0469\*\*\*** |
  | `T50_G440` vs `T10_G440`（同代数） | 1.06× | **+0.0091 n.s.** → T 维度不分层 |
  | `ls_trials 1→3` = **+4.68%\*\*\*** | `RVNSonly_G290`（墙钟 1.03×） | **+0.0027, 14/30, p=0.95 n.s.** |
  | `ls_trials 1→3`（求值次数口径） | `RVNSonly_G586`（同为 58600 次） | **t3 反而差 −5.77%\*\*\*（4/30）** |
  | 「RL 选算子 vs 随机选算子」= +1.86%\* | `G440` 家族（1.06×） | **+0.56%, 15/30, p=0.73 n.s.** |

  同一算法族内 **Spearman(墙钟, HV) = +1.000**（`RVNSonly` G200/290/440/586 与
  `RVNSonly_t3` 落在同一条曲线上：27.7s/0.85975 vs 28.6s/0.86241）。

  > **HV 是墙钟的单一函数；预算"怎么构成"无关，预算"有多少"才有关。**
  > 因此"每代邻域尝试 3 次"（论文 Algorithm 4 的设定）本身没有依据。

- **一个必须写进论文的边界条件：这个基准远未饱和。**
  `RVNSonly` 从 G200 拉到 G586，同盒内 HV **0.82392 → 0.91522（+11.1%）**，
  曲线单调无饱和；而**所有 RL 组件的可测效应都不超过 ±2%**。
  若要主张 RL 机制的价值，必须在一个**代数预算匹配（甚至饱和）**的设定下重做。
- 报**绝对 HV 必须带归一化盒的指纹**（工具：`scripts/hv_box.py`）。
  同一个臂 `QPAS2_hv_wide` 在项目里已有三个公开数值（0.82014 / 0.82795 / 0.83590），
  **全部是盒漂移**；只有 ΔHV / p / wins 可跨批次安全比对。
