# 项目复盘：从 59 个缺陷里读出的规律

> **这份文档是元层面的**：不记缺陷流水（那在 `docs/optimization-report.md`），只记**为什么会反复出错、以及下一次会栽在哪里**。
> 撰写时点：2026-09-27，第十五次复核之后。数据源：`docs/optimization-report.md` 的缺陷台账 + 本轮换路径独立复算。

---

## 结论先行

1. **代码是对的，说法是错的。** 59 个缺陷里，**算法实现只有 1 个真 bug**（缺陷 5：`solve()` 未重置 `self.archive`），其余 58 个全在**实验台 / 交付物 / 文档**。
2. **缺陷是守恒的。** 这一轮给「数字」上了锁，新找出的 4 个缺陷就**全部迁到了「语义」层**。你堵住一面，它换一面。
3. **所以不该问「还有没有缺陷」，而要问「哪一层现在没有判据」。** 目前已知有**四个层是空的**（见 §五），那里就是下一个缺陷最可能出没的地方。

---

## 一、分布：风险不在算法，在「记账」

| 类别 | 数量 | 说明 |
|---|---|---|
| 算法实现真 bug | **1** | 仅缺陷 5 |
| 与论文语义不一致的**真实偏离** | **2** | LS1 算子语义、MIX3 三段拼接顺序（缺陷 54/55 同轮发现） |
| 其余 | 56 | 实验台配置、交付物、文档 |

两条真实偏离也值得单说：它们**逐实例都不显著、且方向一致地「不占便宜」**——即实现"偏"了，但没从偏离里占到好处，所以不是"结果虚高"的问题，而是**声明义务**的问题。全文见 `docs/paper-implementation-conformance.md`。

**这个分布决定了一件事：本项目的复核重点不是「重跑算法验对」，而是「核对说法是否与事实一致」。**

---

## 二、本轮最值得记的观测：数字层已收敛，语义层没有

本轮换了**一条独立路径**重算：直接从 `logs/` 的逐 run 原始行重算 Wilcoxon / 相对差 / 效应量 dz，不复用任何既有聚合脚本。

**结果：14 组数字与文档逐位一致**（RL n=50 四行、LS1 三实例、MIX3 三实例）。

- 这说明**数字层已经收敛**——因为它**有判据管**（`scripts/check_paper_literals.py` 的双向扫、口径锁定、宏化机制）。
- 而本轮新找的 4 个缺陷（56–59），**没有一个是数字错**：ε 极性写反、偏离未同步、markdown 里写 LaTeX 交叉引用、交付物表列了不存在的文件——**全是语义层**。

**这就是「缺陷守恒」的实证**：判据把缺陷从有判据的层赶到了没判据的层。

> **推论**：新增判据的收益，等于**它暴露的盲区大小**；而不是它拦下了多少条。一个「零命中」的判据如果没有 `--self-test`，你无法区分它是"干净"还是"空扫"。

## 三、六条复发定律

这六条都是**同一族**：靠「全库扫 + 语义族判据」解决，不靠「记得改全」。

**① 修复面不全**（缺陷 40 → 49 → 53 → 54 → 57）
同一条被撤回的论断散落多处，**改一处 ≠ 改完**。缺陷 54 第一轮只改了 3 份，全库扫又找出 4 份。缺陷 57 更狠：漏网的下一处是**根级 `doc.md`**——它**在扫描范围内，却不在任何判据的视野内**。
→ **「在扫描范围内」只保证被看见，不保证被判据覆盖。** 每加一类判据都要单独问：它盯着哪一面？谁不在这一面里？

**② 文档命令未实测**（缺陷 19 → 50）
漏必填旗标。读者会以为是自己的环境有问题。

**③ 判据只认一种句式**（缺陷 49 → 51）
被撤回的论断换成**肯定式**表述就漏网。
→ **判据要按「论断的语义族」写，不按上一次的字面句式写。** 第一次修完就该问："这句话还有别的说法吗？"

**④ 检查器没盯着会出问题的那一面**（缺陷 43 → 53）
43：判据读错信号源——Tectonic 的告警写在 stderr，而调用点只喂 `.log`，于是三类判据**自上线起计数恒为 0**。
53：`os.listdir` 不递归 → 仓库门面 `readme.md` 与 `docs/superpowers/**` **从未被任何守卫看过**。
→ **覆盖面必须由「哪些文档需要检查」定义，绝不能由「glob 恰好展开成什么」定义。**

**⑤ 审计基准自己错了**（缺陷 54 → 55）
核对「实现 vs 论文」时用**二手中文译本**当基准。译本把 LS1 译成"随机选两个工序交换位置"，于是「实现也用了『随机』」这个**共同词**，掩盖了「随机选的是什么」的**根本差别**。
→ **凡「实现与论文一致」的结论，必须能追到一手材料（原始 PDF）的那一句。** 任何「权威源」在被当基准之前，**先验它自己**。

**⑥ 判据要能区分「主张」与「提及」**
写缺陷 56 的勘误表时，**判据把我自己刚写的勘误报成了新缺陷**——因为勘误表必须逐行引用错误写法。
→ **写「禁止某种写法」的判据，必须先留出「引用该写法」的出口**（被行内代码/引号包住 = 在引用，放行；裸写仍判错）。否则第一个被拦下的，就是**记录这条禁令的那段文字**。

## 四、做对的四件事（值得保持）

1. **每条教训都变成判据，而不是写进文档就完事。** 「写下来」是最弱的形式；「有脚本每次跑」才是有牙齿的。
2. **每条判据都配突变验证**（`scripts/mutation_check_caliber_claim.py`，现 9 条）。它同时证明两件事：判据**有区分度**（突变后必须失败）+ 改动**可还原**（md5 一致）。
3. **每条判据都防「空扫」**（`--self-test`）。这是从缺陷 43 学到的：看着在工作，其实一条都没看过。
4. **如实声明盲区**（§五）。这是四件里最少人做、也最有价值的一件——**它把「不知道」变成了可审计的对象**。

---

## 五、已知的四个判据盲区（下一个缺陷的出没地）

1. **口径锁只认具体数字，不认「族」。** 它只扫 `1.86%` 与 `0.01658`〔两者同为盒口径〕，同族的 `+2.19%`、`+5.68%`、`+0.31%`、`0.82014`/`0.82795`/`0.83590` **不在集合内**。放宽会刷假阳性，故保持窄——**但引用时必须说清「覆盖的是哪两个数字」，不能说成「覆盖了那一族」。**
2. **路径判据只覆盖 `docs/**/*.md` 与仓库根级 `*.md`**，**不覆盖 `src/`、`scripts/` 里的字符串常量**（那些字符串会打进日志、被读者看到，属缺陷 41 那一类"没人看的那一面"）。
3. **没有任何判据检查「论文 §5.5 的 5 条偏离是否同步到每份文档」**——这正是缺陷 57 的成因。
4. **「论断层」完全没有判据。** 现在只锁了**数字**，没锁**论断**：例如「天花板为 0」这句论断写在文档的哪几处、口径是否一致——**没有任何机器在看**。

> **盲区 4 是下一个最可能出缺陷的地方**：数字有主，论断无主。

## 六、要警惕的四件事

1. **「人工全库扫」已被当作收尾机制用了 5 次**（40 / 49 / 53 / 54 / 57）。**它不可靠**——每次都能漏，每次都要再扫一遍。真正的解法只有一个：**按语义族加锁**。人工扫只应作为"建锁之前的临时兜底"。
2. **判据的覆盖面天然滞后一轮。** 判据是照着"上一轮已知的缺陷"写的，所以**必然漏掉"这一轮才出现的新形态"**。这不是努力程度问题，是结构问题——**所以才要显式声明盲区，而不是宣称"已全面覆盖"**。
3. **本文档自身可能就是"没人看的那一面"。** 文档越多，新文档成为新盲区的概率越高（缺陷 57 的 `doc.md` 就是活例：它在扫描范围内，却不在任何判据的视野内）。**判断一份新文档有没有价值，标准是「它有没有被引用、有没有驱动一个判据」，不是「它写得多完整」。**
4. **别把「跑绿了」当成「验过了」。** 本项目的三个判据都曾"绿着但无效"（缺陷 43 计数恒为 0、缺陷 53 反斜杠命令 0 命中、缺陷 49/51 只认一种句式）。**绿灯的价值取决于它看得见什么。**

## 七、下一步（按优先级）

1. **给「论断层」建判据**（§五 盲区 4）：先做「同一论断多处出现、口径必须一致」的全库扫描——例如锁定「天花板为 0」「与 0 不可区分」这类关键论断的每一处出现，逐处核对口径标记。
2. **「偏离同步」的指纹扫描**（§五 盲区 3）：给论文 §5.5 的 5 条偏离各配一个关键词指纹，全库扫并要求**上下文带「偏离 / 不一致 / 不同」标记**。
3. **口径锁**（§五 盲区 1）：要么扩成可维护的「盒口径指纹清单」，要么明确保持窄 + 每次人工兜——**两条路都可以，但不能两条都不选**。
4. **第二轮热路径优化**（工程侧，与本复盘无关但同属待办）：`src/` 已解冻，可起；门槛仍是「随机流逐位不变」。
