# 消融实验诊断：Q-PAS 与 RVNS 的贡献为何不对称

> ⚠️ **归因修正（见 §8）**：本文早期版本把 Mk10 上 +5.7% 的增益记在 "RVNS" 头上，并据此
> 称"RVNS 是显著的一等功臣"。补上论文缺失的对照臂 **RandVNS（论文 RMOEA/D3 的随机选择
> VNS）** 后证明：这 +5.7% **几乎全部来自「加上局部搜索本身」**，而 **"RL 引导选算子 替代
> 随机选算子" 只有 −0.25%（p=0.53 n.s.）**。
> 也就是说：**局部搜索有效（+5.7%），但 RVNS 的 RL 机制在论文的 `ls_trials=1` 设置下没有
> 可检测贡献**——这与论文自己阶梯里 RVNS 那一步只有 +0.15%（p=0.68）完全吻合。
> 完整对照见 `docs/paper-vs-reproduction.md` 与图 `charts/ablation/paper_vs_reproduction.png`。
>
> 结论先行（已修正）：**原代码存在 4 个真实 bug，修掉后局部搜索的贡献从「测不出来」变为
> 「显著」（+5.7%）；但 RVNS 的 RL 选算子机制、以及 Q-PAS，在论文设置下都没有显著贡献。**
> 关于 Q-PAS，两个实例给出了**不同的答案**：
>
> - 在 **Mk01**（10×6）上它的 null 是**实例特性**——该实例上邻域大小 T 本身是弱杠杆
>   （固定 T 扫参 Friedman p=0.15，连 per-seed oracle 都测不出显著差异）；
> - 在 **Mk10**（20×15）上 T **是强杠杆**（Friedman p=4.7e-05\*\*\*，HV 极差 6.5%），
>   最优 T=50。此时 Q-PAS 的失效**不是**实例特性，而是第 4 个 bug：**Q 表零初始化 +
>   `np.argmax` 平局取索引 0 + ε=0.8（80% 利用）⇒ 策略自锁在最差的 T=5**，
>   实测 47%~53% 的代数停在 T=5。修复平局口径后，Q-PAS 从「显著劣于最优固定 T」
>   变为「与之打平」（§7）。
>
> 要点：**「Q-PAS 无效」这一结论只在 Mk01 这类小实例上成立**；在 T 真正有杠杆的
> 实例上，之前测到的 null 主要是实现缺陷造成的。

## 1. 发现了 3 个真实 bug（已修复）

### 1.1 HV 指标口径错误 —— 这是"看不出差异"的**首要原因**

原 `compute_hv` 在未给归一化边界时，用**每条前沿自己的 min/max** 归一化：

```python
lo, hi = front.min(axis=0), front.max(axis=0)   # ← 每条前沿各归一化一次
```

这会把任意前沿都拉伸到单位盒，指标只反映**前沿形状**，对**整体优劣不敏感**——
两个质量差异很大的算法会得到几乎相同的 HV。

**修复**（`utils/metrics.py`）：新增 `estimate_hv_bounds()` / `instance_hv_bounds()`，
改用**参考集归一化**（reference-set normalization）——以同一实例下所有变体、所有
run 的前沿并集作为共用归一化盒，参考点 `(1.02, 1.02)`。这是多算法比较 HV 的标准做法。
同时修正扫掠公式为 `∪[p, ref]` 支配区域并集（原先多算了前沿左侧的空条带）。

**效果**（mk01，同一批数据）：

| 口径 | Friedman p | 能否区分算法 |
|---|---|---|
| 旧（自归一化） | 0.668 | ✗ 四个变体无差别 |
| 新（参考集归一化） | **0.0046** | ✓ 差异显现 |

### 1.2 RVNS 接受准则与论文不符

论文 Algorithm 4 的接受准则是 **Tchebycheff 标量化**：

```
g^te(P'|λ,Z) < g^te(P|λ,Z)
```

原实现用的是 Pareto 支配判定，且**传入的 weight / z 参数完全没有被使用**。
后果：收敛后期接受率塌到 0/100，RVNS 实际失效。

**修复**（`core/rvns.py`）：改用 Tchebycheff 接受准则，复用 `moead.tchebycheff`。

### 1.3 Q-PAS 的 ε-greedy 极性写反

论文 Section 4.5.5 明确说明该 ε-greedy **与常规写法相反**：

```
if rand < ε:  选 max Q 的动作（利用）
else:         随机（探索）
```

原实现写成 `rand < ε → 随机`，于是 ε=0.8 的实际含义变成 **80% 随机探索**，
Q-table 基本学不到东西。

**修复**（`core/qlearning.py`）：按论文极性修正。
修复后 Q-table 确实出现梯度（`T=5` 偏好，极差 ≈1.99），但见第 3 节——
**学到的是"错误的" T**。

## 3. 为什么 Q-PAS 无效（根因链）

### 3.1 Q-PAS 在数学上等价于「选最常改善 DV 的那个 T」

`reward = 10·[ΔDV>0]`，且 `next_state` 由 (ΔCV, ΔDV) 的符号决定。
因 `reward` 是 `next_state` 的确定函数，Q 值收敛到

```
Q[s,a] ≈ 10·P(ΔDV>0 | s,a) / (1 − γ)
```

实测 Q 值上限 ≈ 5.17，与 `2/(1−0.6)=5` 吻合，确认该退化。
于是 `argmax` 等价于**「选让间距指标 DV 最常变大的 T」**。

实测（mk01，20 seeds，3980 个决策步）：

| T | P(ΔDV>0) |
|---|---|
| 5 | **0.2421** ← 最高 |
| 10 | 0.2010 |
| 15 | 0.1501 |
| 20 | 0.2080 |

奖励与动作**显著相关**（χ²=24.45, p=2.0e-05），所以 Q 确实有信号可学——
**只是这个信号把策略推向 T=5。**

### 3.2 学到的策略退化

论文 Table 3 的 Q-table 是丰富多变的（State1→T20, State2→T20, State3→T5, State4→T15），
本实现退化为：

```
argmax(T) = [T5, T5, T5, T10]    ← 不同动作数仅 2（论文为 3）
```

即 Q-PAS 几乎恒定选 T=5。

### 3.3 T 在 Mk01 上是弱杠杆（决定性证据；该结论**不外推**到 Mk10，见 §7）

固定 T 扫参（mk01，`enable_rvns=False`，T∈{5,10,15,20,50} × 30 seeds）：

| 固定 T | HV mean | bestMS |
|---|---|---|
| 5 | 0.78600±0.07937 | 43.31 |
| 10 | **0.79859±0.07014** | 43.39 |
| 15 | 0.79768±0.07984 | 43.58 |
| 20 | 0.79351±0.08333 | 43.88 |
| 50 | 0.78287±0.08021 | 44.30 |

Friedman across T **p = 0.15**，HV 均值极差仅 **0.0157**。
最关键的一条：**即使换成"先知"策略、永远选最优的 T=10，相对最差的 T=5 也只有
ΔHV=−0.0126、p=0.077（未达显著）**。

→ 在 Mk01 这个 T 维度上「连 oracle 都测不出显著差异」的实例里，
任何自适应选 T 的策略（Q-PAS）都**不可能**产生可检测的主效应。

**但这条推论只对 Mk01 成立。** Mk10 上 T 是强杠杆（§7.1：Friedman p=4.7e-05\*\*\*、
最优 T=50 相对 T=5 高 6.8%），因此 Mk10 上 Q-PAS 仍然失效这件事**必须另有解释**——
查下去是一个实现缺陷（§7.2），而不是实例特性。

### 3.4 奖励目标与优化目标错位

上述链条的实质是：论文式 (20) 只奖励「间距指标 DV 变大」，
而 **DV（间距均匀度）与 HV（收敛+多样性的合成）并不单调一致**。
DV 偏好的 T=5，恰是最终 HV 最差的一档。

## 4. 尝试过的"优化"及其结果（均无效，故未采纳为默认）

在 `qlearning.py` 中新增了可选的 `reward_mode`（默认 `"dv"` 仍严格照论文）：

| 模式 | 奖励定义 |
|---|---|
| `"dv"` | 论文原始：ΔDV>0 → 10（默认） |
| `"cv_dv"` | ΔCV>0 与 ΔDV>0 各计 5 分 |
| `"hv"` | ΔHV>0 → 10（奖励直接对齐最终指标） |

A/B 实验（Mk01，6 组 × 30 seeds，统一参考集归一化）：

| arm | HV mean±std | vs baseline |
|---|---|---|
| baseline / T10_fixed | 0.80897±0.06711 | — |
| R_dv（论文口径） | 0.80910±0.07281 | ΔHV=+0.00013, p=0.63 n.s. |
| R_cv_dv | 0.80722±0.07479 | ΔHV=−0.00175, p=0.89 n.s. |
| R_hv（对齐目标） | 0.80917±0.07852 | ΔHV=+0.00020, p=0.86 n.s. |
| R_hv_e05（ε=0.5） | 0.80430±0.07124 | p=0.87 n.s. |

Friedman **p = 0.857** —— 6 组之间毫无差别。

**结论：换奖励、换探索率都救不了 Q-PAS。** 根因是 T 维度本身无效，不是奖励设计问题。
`reward_mode` 作为可复用开关保留在代码中（默认不改论文口径）。

> ⚠️ **一个被否决的"发现"**：若只看"前沿延展度 EXT"，`qpas_only` 比 baseline 高
> +13.3%（p=0.017），看起来像"Q-PAS 提升了多样性"。但拆解两端后证伪：
> **best 角（好端）无差异（p=0.68），EXT 的增量几乎全部来自 worst 角（差端）显著变差
> （+0.0530, p=0.0137）**——即前沿变宽是"混入了更多劣解"的假象，不是多样性收益。
> 该指标**不应**写入论文。

## 5. 需要提醒的一个方法学问题

`MOEADBaseline` 是 `RMOEAD` 的子类，仅覆盖元数据：

```python
class MOEADBaseline(RMOEAD):
    def __init__(self, ...):
        super().__init__(..., fixed_T=fixed_T, enable_rvns=False,
                         algorithm_name="MOEA/D", algo_dir_name="MOEA_D")
```

因此消融表中的 **`moea_d` 与 `T10_fixed` 的 HV 逐位相同**（0.80897/0.06711/0.80588/43.39）。

- 作为**消融对照**这是合法的：它等于"RMOEA/D 框架剥掉两个 RL 组件"，
  正好用于逐个剥离 Q-PAS / RVNS。`qpas_only vs moea_d` 精确隔离 Q-PAS，
  `rvns_only vs moea_d` 精确隔离 RVNS——这正是消融该做的事。
- 但若论文把它当作**独立的"标准 MOEA/D"对比算法**，会被审稿人质疑：
  它同时继承了 MIX3 初始化、模糊解码、MOEA/D 生成算子与精英存档。
  **建议**：把它明确命名为 "RMOEA/D w/o RL components (ablation control)"；
  若需要"vs 标准 MOEA/D"的对比，应另写一个真正的独立实现。

## 6. 建议

### 6.1 论文里怎么写这个消融（诚实且稳）

1. **主打 RVNS**：Mk01 +0.0097 (p=0.031\*)、Mk10 +0.0481 (p=4.8e-05\*\*\*)，
   主效应 p=0.0022\*\* / p=3.8e-06\*\*\*，两个实例一致 → 是可靠的贡献点。
2. **完整版（两者都开）最强**：Mk01 +0.0170 (p=0.025\*)、Mk10 +0.0586 (p=6.3e-05\*\*\*)。
3. **Q-PAS 按实际情况写**：主效应不显著（p=0.46 / p=0.45），
   但 (a) **几乎零额外开销**（Mk01 6.7s vs 6.7s；Mk10 15.4s vs 15.7s），
   (b) 叠加在 RVNS 之上时方向一致为正（+0.0073 / +0.0104），
   (c) 在 T 维度无效的实例上是**预期的 null**，并给出 T 扫参（p=0.15）作为佐证。
   这样写比硬凑显著性更站得住。
4. **不要**把 EXT 的"多样性提升"当作 Q-PAS 的功绩（见 §4 的证伪）。

### 6.2 想救 Q-PAS，唯一有希望的方向

T 的有效性依赖实例的**决策空间复杂度与种群规模之比**。Mk01 是 10×6 的小实例，
Np=100 已远超问题规模，邻域大小 T 自然无所谓。建议：

- 在**更大实例**（Mk06–Mk10）上重跑 T 扫参，定位 T 开始有影响的规模阈值；或
- **增大 Np**（如 Np=200）配合大实例，观察 T 是否成为有效杠杆；
- 若确认 T 在某些规模下有效，Q-PAS 的价值就能在该子集上被验证。

> **→ 已执行**：在 Mk10 上跑完 T 扫参 + Q-PAS 全设定（23 臂 × 30 seeds）。
> 结论与本文其余部分相反——T 在 Mk10 上是强杠杆，且 Q-PAS 的失效源于实现缺陷。
> **请以 §7 为准。**

### 6.3 工程侧已完成

## 7. Mk10 复验：T 是强杠杆，Q-PAS 的失效是第 4 个 bug

> 实验台：`scripts/t_leverage_sweep.py` + `scripts/t_leverage_analysis.py`
> （23 臂 × 30 seeds = 690 runs，Mk10，Np=100 / G=200，HV 统一参考集归一化，ref=(1.02,1.02)）
> 原始结果 `logs/_mk10_lab.json`；图 `charts/ablation/mk10_t_leverage_qpas_fix.png`。

### 7.1 T 在 Mk10 上是强杠杆（与 Mk01 相反）

固定 T 扫参（关闭 Q-PAS 与 RVNS，n=30）：

| 固定 T | HV mean±std | vs T=10 |
|---|---|---|
| 5 | 0.77196±0.0434 | −0.0336, 8/30, p=6.1e-04 \*\*\* |
| 10 | 0.80553±0.0371 | — |
| 15 | 0.82176±0.0472 | +0.0162, 19/30, p=0.084 |
| 20 | 0.81082±0.0398 | +0.0053, 15/30, p=0.67 |
| **50** | **0.82471±0.0589** | **+0.0192, 19/30, p=0.019 \*** |
| 100 | 0.80721±0.0617 | +0.0017, 14/30, p=0.82 |

Friedman over T∈{5,10,15,20,50,100}：**p = 4.7e-05 \*\*\***，HV 均值极差 **0.0528（6.5%）**。
对照 Mk01（p=0.15、极差 0.016）——**T 的杠杆强度随实例规模增长**。

per-seed oracle（每个 seed 取最优 T）达 **0.86644**，比最优固定 T=50 还高 **+0.0417**：
按状态自适应选 T 在这个实例上**理论上确有可观空间**，Q-PAS 若真能自适应就该超过任何固定 T。

### 7.2 第 4 个 bug：Q-PAS 自锁在最差的 T=5

`select_action` 的利用分支是 `np.argmax(self.q_table[state])`。Q 表零初始化 ⇒ 全表 Q=0
⇒ `argmax` 恒返回**索引 0 = `actions[0]` = T=5**；而论文 ε=0.8 是 **80% 利用**
（§1.3 的"反向"极性）。于是前期几乎每一步都落到 T=5，一旦它拿到奖励，
`Q[·,0]` 被抬高 ⇒ **越用越锁**。

实测"选择 T=5 的代数占比"：

| 变体 | T=5 占比 | 动作空间 |
|---|---|---|
| QPAS_dv（论文配置） | **47.3%** | {5,10,15,20} |
| QPAS_cv_dv | **50.3%** | {5,10,15,20} |
| QPAS_hv | **50.8%** | {5,10,15,20} |
| QPAS_wide（含 T=50） | **50.1%**（T=50 仅 16.8%） | {5,10,20,50} |

而 T=5 恰是全表**最差**一档（HV 0.7720）。**修不修平局，直接决定 Q-PAS 是负收益还是打平。**

### 7.3 修复与效果

**修复**（`core/qlearning.py`）：并列最大时默认随机取（`tie_break="random"`）；
新增可选 `q_init="optimistic"` 进一步打破对称；`tie_break="argmax"` 保留以复现旧行为。
回归测试：`tests/test_refactor.py::TestQlearningTieBreak`。
RMOEAD 透传参数 `ql_tie_break` / `ql_q_init` / `ql_q_init_scale`。

修复后 HV（同批 n=30；基准：最优固定 T=50 = 0.82471、T=10 = 0.80553）：

| Q-PAS 变体 | HV | vs T=10 | vs T=50 | T=5 占比 |
|---|---|---|---|---|
| QPAS_dv（旧） | 0.79678 | −0.0088 n.s. | **−0.0279 \*** | 47.3% |
| QPAS_wide_hv（旧） | 0.79274 | −0.0128 n.s. | **−0.0320 \*\*** | 52.6% |
| QPAS2_dv | 0.81044 | +0.0049 n.s. | −0.0143 n.s. | 27.1% |
| **QPAS2_hv_wide** | **0.82014** | **+0.0146 n.s.** | **−0.0046 n.s.** | 27.7% |
| QPAS2_opt_wide | 0.81363 | +0.0081 n.s. | −0.0111 n.s. | 18.5%（T=50: 33.9%） |
| QPAS2_opt_hv | 0.81350 | +0.0080 n.s. | −0.0112 n.s. | 16.5%（T=50: 38.3%） |

**修复后所有 Q-PAS 变体从「显著劣于最优固定 T」转为「与之打平」**（HV 提升 +0.014~0.027）。
最优修复配置：`tie_break="random" + reward_mode="hv" + actions=[5,10,20,50]`（QPAS2_hv_wide），
0.82014，与 T=50 差距 −0.0046 不显著，数值上高出 T=10 0.0146。

### 7.4 仍未解决：Q-PAS 追不上 per-seed oracle

修好平局后 Q-PAS 最好也只到 **0.82014**，而 oracle 是 **0.86644**（gap −0.0463）。即：

- **Q-PAS 目前只能"不输给一个好默认"（T=50），无法兑现"自适应优于固定"的宣称**；
- oracle gap 说明空间存在，受限的是 Q-PAS 的信息量——只有 4 个由 (ΔCV,ΔDV) 符号
  划分的离散状态 + 二值即时奖励，不足以做精细的阶段化选择。

后续可试（**未验证**，仅记录方向）：基于 HV 趋势/代数阶段的更细状态划分。
本轮已实现的连续奖励 `reward_mode="hv_cont"` 实测**未**优于二值 `hv`（QPAS3_hvc 0.80535）。

### 7.5 反面结果（一并记录，避免重复踩）

- **奖励模式不是关键**：`dv / cv_dv / hv / hv_cont` 两两差异均不显著
  （Friedman over 15 组 p=0.014\* 主要由**旧** Q-PAS 的劣势驱动）。
- **放宽动作空间不是万能药**：把 T=50 放进候选，若不平局随机，仍只被选中 16.8%。
- **动作空间更大也没更好**：`[5,10,15,20,30,50]`（QPAS2_hv_fine, 0.81206）不如 `[5,10,20,50]`。
- **RVNS 仍是主力**：Full/Full2/Full3 = 0.86166 / 0.86551 / 0.86528，显著优于
  所有单 T 与所有 Q-PAS 配置（+0.037~+0.073，p<0.01）。

  > ⚠️ **该条已被 §8 修正**：这里的对比基准（`T10`）里**没有局部搜索**，所以
  > "Full 优于 T10" 测到的其实是「加上局部搜索」，不是「RL 引导选算子」。
  > 正确表述见 §8.2。

### 7.6 论文里该怎么写（更新版，取代 §6.1 的第 3 点）

1. **RVNS 照旧主打**（两实例一致，p=0.0022\*\* / 3.8e-06\*\*\*），Full 最强。
2. **Q-PAS 要分实例叙述**：Mk01 上给 T 扫参 p=0.15 说明"该实例 T 维度无效，
   Q-PAS 的 null 是预期的"；Mk10 上先给 T 扫参 p=4.7e-05\*\*\* 证明 T 有效，
   再给平局修正后的 Q-PAS 结果（0.82014，打平最优固定 T）。
   **不要**沿用旧的 Mk10 数字（那批数据带平局自锁缺陷）。
3. **诚实交代 oracle gap**：明确 Q-PAS 当前只是"追平最优默认 T"，不声称超过固定 T；
   把 per-seed oracle（0.86644）作为 future work 的上界，反而更有说服力。
4. 平局随机化属于**实现细节修正**（论文未规定平局取舍），可在附录一句话说明。

## 8. 组件分解修正：把「加上局部搜索」与「RL 引导选算子」拆开

论文的消融阶梯里，**随机选择的 VNS 早在 RMOEA/D3 就已就位**，所以它测的 RVNS 增益
（D5 → RMOEA/D）是"RL 引导选算子"的净贡献，不是"加上局部搜索"。

本项目的消融阶梯缺了这一环——`baseline` (`T10`) **完全没有局部搜索**，因此
`RVNS only vs baseline` 把两件事混在了一起。补齐论文缺失的 **`RandVNS`** 臂
（五算子等概率随机选，见 `core/rvns.py` 的 `mode="random"`）后，同强度配对比较：

**Mk10，n=30，参考集归一化（28 臂 / 840 runs）**

| 对照（同强度） | ΔHV | 胜负 | 相对 | p |
|---|---|---|---|---|
| 加上局部搜索本身（算子随机选） | +0.04671 | 24/30 | **+5.68%** | 1.8e-05 \*\*\* |
| **RL 引导选算子 替代 随机选算子** | **−0.00219** | 13/30 | **−0.25%** | **0.53 n.s.** |
| 在已有局部搜索上再加 Q-PAS | +0.00482 | 19/30 | +0.56% | 0.28 n.s. |
| Q-PAS 单独（无局部搜索） | +0.01281 | 17/30 | +1.56% | 0.27 n.s. |

**结论**：+5.7% 属于**局部搜索**，不属于 RVNS 的 RL 机制。本文 §1.2 修的接受准则 bug
仍然是真 bug（修前 RVNS 后期空转），但修好后**RL 引导选算子本身依然测不出贡献**——
原因见 §8.1 的 ls_trials 交互。

### 8.1 为什么 RL 选算子没贡献：`ls_trials=1` 让它没有发力空间

论文 Algorithm 4 是 **first-improvement 单步** VNS：每个解每代只尝试 1 次邻域就返回。
只有一"枪"时，选哪个算子差别不大；RL 的记忆机制要累积多轮选择才有意义。

| 对照 | ΔHV 相对 | 胜负 | p |
|---|---|---|---|
| RL 引导 vs 随机选算子，`ls_trials=1`（论文设置） | −0.25% | 13/30 | 0.53 n.s. |
| RL 引导 vs 随机选算子，`ls_trials=3` | **+1.86%** | 21/30 | **0.045 \*** |
| 邻域尝试 1 → 3 次（同样本内） | **+4.68%** | 24/30 | 3.5e-05 \*\*\* |

→ **给足尝试次数，RL 引导才转为正贡献**；而且"尝试次数"本身就是全场最大的单一杠杆
（+4.68%，大于任何奖励/动作空间/平局设定）。`RVNSonly_t3` 达 **0.90819**，是全部 28 臂最高，
显著高于所有 `Full` 配置（0.872~0.876）。

### 8.2 修正后的贡献排序（Mk10）

| 组件 | 相对增益 | 显著性 |
|---|---|---|
| 每代邻域尝试 1 → 3 次 | +4.68% | \*\*\* |
| 加上局部搜索本身 | +5.68% | \*\*\* |
| RL 引导选算子（需 `ls_trials≥3`） | +1.86% | \* |
| Q-PAS 单独 | +1.56% | n.s. |
| Q-PAS 叠加到局部搜索上 | +0.56%（t=1）/ −1.49%（t=3） | n.s. |

**Q-PAS 在任何语境下都没达到显著，且在强局部搜索下符号转负。**
不能作为显著贡献点写入论文。
