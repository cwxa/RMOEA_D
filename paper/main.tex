\begin{abstract}
\noindent
一批工件要在多台机器上依次加工、每道工序可以任选机器、实际耗时事先说不准，
怎样安排才能既缩短总工期又均衡机器负载？这类\textbf{双目标模糊柔性作业车间调度
问题}是典型的 NP 难组合优化问题。Li 等（2022）提出的 RMOEA/D 用 Q-learning
同时驱动参数自适应（Q-PAS）与变邻域算子选择（RVNS），在该问题上报告了良好效果。
本文在 Brandimarte Mk01--Mk10 上对该算法做了可复现的重实现，并在统一评价口径下
重新审计其每个组件。本文的工作有三点。

\textbf{其一，评价口径。} 文献与复现中普遍使用的一种归一化取法——按参与比较的
前沿确定边界（下称盒口径）——有\textbf{两个结构性缺陷}：边界随实例集与臂集漂移，
且系统性放大效应量。实测同一批数据下按臂对汇总的放大为 $\CalibAmpLo\times$ 至
$\CalibAmpHi\times$、逐格子最高 $\CalibAmpMax\times$，\textbf{倍数并非常数}；
更严重的是它会改变现象的形状：把“少数实例显著、其余与 0 不可区分”抹成
“处处微小为正”。本文因此主张改用由实例数据确定性推出的\textbf{实例边界口径}，
并给出可复现的对照证据。

\textbf{其二，组件有效性的重新判定。} 在实例边界口径下，六个阶梯臂的逐级增量为
MIX3 初始化 $\LadderMixRel\%$（\LadderMixWins\ 实例胜出）、随机 VNS $\LadderVnsRel\%$、
精英档案 $\LadderEliteRel\%$，而 Q-PAS 仅 $\LadderQpasRel\%$（$p=\LadderQpasP$，不显著）、
RL 选算子 $\LadderRlRel\%$。进一步用 anytime 轨迹证明算力在 $G=\SetG$ 附近已接近饱和，
因此 RL 组件的失效不是“学不到”，而是\textbf{没有空间可学}。

\textbf{其三，可事前判定的增益。} 我们提出一个零代探针：只调用一次初始种群构造
（不做任何搜索），用初始前沿 HV 的杠杆 $\lam$ 预测“某个新实例上 MWR 初始化相对
论文口径是否真有净增益”，并在 Hurink $e$-data 的\textbf{全部 \HKn\ 个}实例上做
完全预注册的留出验证。\textbf{该门控没有通过这次检验}：它在开发集上与净增益完全分离，
在留出集上的判对率却低于“一律拒绝”这条平凡基线，放行实例的精确率仅 $\HKpassPrec$。
我们据此把“廉价零代门控可以跨分布移植”这个常见默认写成明确的负结果。

\vspace{4pt}
\noindent\textbf{关键词：} 柔性作业车间调度；分解型多目标进化算法；模糊加工时间；
强化学习；消融实验；评价口径；可复现性
\end{abstract}

\section{引言}
%======================================================================

\paragraph{问题从哪里来。}
工厂排产有个日常难题：一批\textbf{工件}要依次经过多道\textbf{工序}，每道工序占用一台
\textbf{机器}，怎么安排才能既让整批活尽早干完、又不让少数机器长期超载？若每道工序
可以在多台机器中任选（称\textbf{柔性}），可选方案数随规模指数增长；若各工序的实际
耗时事先说不准（称\textbf{模糊}），问题更难。这类\textbf{双目标模糊柔性作业车间调度
问题}（bi-objective fuzzy flexible job-shop scheduling problem, FFJSP）是典型的
NP 难组合优化问题，要在“工期”与“负载均衡”两个互相冲突的目标之间做取舍
（这些概念在 \S\ref{sec:prelim} 有面向非专业读者的说明，不熟悉的读者可先读那一节）。

近年的主流做法是把\textbf{进化算法}与\textbf{强化学习}结合：让算法在搜索过程中
“学会”自己的参数该取多少、该用哪种局部搜索算子。Li 等\cite{li2022rmoead}
提出的 RMOEA/D 即属此类——它把 Q-learning 同时接在两个决策点上：一是每代选择
Tchebycheff 分解中的参数 $T$（该文称 Q-PAS），二是选择变邻域搜索的算子（RVNS），
并在 Brandimarte 基准上报告了相对基线的改进。

\paragraph{复现中的两个隐形陷阱。}
复现这类“学习型元启发式”时，有两个容易出错、且出错方式很隐蔽的地方——
它们\emph{不会报错，只会悄悄改变结论}：

\textbf{(1) 多目标指标的评价口径。} 超体积（HV）需要把两个目标归一化到同一量纲。
把归一化边界取为“参与比较的前沿的极值”（盒口径）是一行代码就能写出的做法，
但它使边界成为一个\textbf{依赖于臂集与实例集}的量：同一份数据，只要换掉比较对象，
HV 读数就变。这在复现里意味着一个组件“有没有效果”的结论会随同批实验的设计而漂移。

\textbf{(2) 比较基准与问题的不对齐。} 当要回答“该不该用我们提出的初始化”时，
正确的对照是\textbf{论文自己的初始化}；而“随机初始化”只能回答“有个好起点值多少”。
这两个量在同一批数据上都算得出来，但用前者去论证后者是无效的。

\paragraph{本文主要发现（一段话）。}
在统一、可复现的评价口径下，本基准与算力预算之内真正有效的是\textbf{初始化}
（即搜索起点）与\textbf{算力总量}（且后者很快饱和）；两个 RL 组件没有可实现空间——
这并非“学习算法不行”，而是它在\textbf{两个方向上都没有事可做}。在建设性的一面，
我们提出一个廉价的\textbf{零代探针}，用于事前判定“某个新实例上初始化的净增益
会不会出现”，并在全部 \HKn\ 个独立实例上做完全预注册的检验——\textbf{它没有通过}：
跨到留出集之后，它的判别力低于“一律拒绝”这条平凡基线。本文把这条负结果
完整报告出来，它正是本文方法学主张的自我检验：门限若只在挑出它的那批实例上成立，
就不能算门控。

\paragraph{阅读地图。}
只关心结论的读者读本节与 \S\ref{sec:res}、\S\ref{sec:hurink}、\S\ref{sec:concl} 即可；
关心方法学的读者重点看 \S\ref{sec:caliber}（评价口径）与 \S\ref{sec:stat}（统计口径）；
想复现的读者请从 \S\ref{sec:setup} 与随文脚本入手。

\paragraph{贡献。}
\begin{itemize}\itemsep2pt
  \item 量化了盒口径的偏差：同一批数据、同一臂对，效应量被放大约一个数量级，
        且\textbf{放大倍数不是常数}（按臂对汇总 $\CalibAmpLo\times$--$\CalibAmpHi\times$，
        逐格子最高 $\CalibAmpMax\times$），
        显著性检验的 $p$ 与胜出场数同样改变（\S\ref{sec:caliber}）。
  \item 在实例边界口径下重新给出六臂消融阶梯的逐级效应，并把“算力饱和”量化，
        由此把 RL 组件的失效解释为\textbf{动作空间与算力上都没有空间}（\S\ref{sec:res}）。
  \item 提出零代探针门控（$\lam$ = 初始前沿 HV 杠杆）：它在开发集上与净增益完全分离，
        但在 \HKn\ 个实例的预注册留出集上\textbf{没有通过}——判对率 $\HKaccHold$ 低于
        “一律拒绝”的平凡基线 $\HKaccRejectAll$，放行实例的精确率仅 $\HKpassPrec$，
        召回仅 $\HKrecall$（\S\ref{sec:hurink}）；此外回答“门控需要多少 seed”（\S\ref{sec:seedvar}）。
  \item 全部脚本、原始日志与“一个数字一个来源”的导出流程随文公开，
        论文中每个数字都由 \texttt{scripts/paper\_export.py} 从 \texttt{logs/} 现场生成。
\end{itemize}

\section{预备知识：读懂本文所需的五个概念}\label{sec:prelim}
%======================================================================
本文的方法学结论不依赖多目标优化的专门知识，但需要先建立下面几个概念。
每小节末尾用一句话说明“在本文中”它对应什么；已经熟悉这些内容的读者
可只读那一句，再跳到 \S\ref{sec:caliber}。表~\ref{tab:glossary} 是全文记号速查。

\subsection{车间调度：在不确定中把活排完}
一个车间有若干\textbf{工件}（待加工的产品）和若干台\textbf{机器}。每个工件要依次
经过若干道\textbf{工序}，每道工序占用一台机器、消耗一段时间。调度要决定两件事：
\textbf{每道工序派给哪台机器}、\textbf{同一台机器上谁先谁后}。若每道工序只能由
一台指定机器完成，这类问题叫作业车间调度（JSP）；若每道工序\emph{可以在多台
机器的任一台}上完成，就叫\textbf{柔性}作业车间调度（FJSP）——“柔性”留下了取舍空间，
也正是算法要去搜索的东西。

现实中加工时间很少提前精确已知。本文沿用复现对象\cite{li2022rmoead} 的做法，
把每道工序的加工时间写成一个\textbf{三角模糊数} $\tilde t=(t_1,t_2,t_3)$：
$t_1$ 为乐观值、$t_2$ 为最可能值、$t_3$ 为悲观值。模糊数之间的比较与折算规则
同样沿用该文约定（\S\ref{sec:prob}）。由于模糊区间由实例与随机种子共同决定，
同一实例在不同种子下得到的时间并不相同——这一点直接决定了本文的统计做法
（\S\ref{sec:stat}）。

\noindent\textbf{在本文中：}这句话解释了两个纪律的来源——为什么所有比较都要
\textbf{同种子配对}，以及为什么结论必须在多个实例上重复才可信。

\subsection{两个互相冲突的目标：没有“唯一最优解”}
本文同时追求两件事：\textbf{整批活尽早干完}（最大完工时间 $C_{\max}$，最后一道工序
的结束时刻）与\textbf{机器负载不要过度集中}（机器总负载 $W$，各机器负荷之和）。
这两个目标会打架：想缩短 $C_{\max}$，常要把工序塞给空闲机器，总负载反而上升；
想压低总负载，又可能把工期拖长。因此\textbf{不存在“两个目标都最好”的单一排产方案}。

比较两个方案的办法叫 \textbf{Pareto 支配}：若方案 A 的两个目标都不比 B 差、
且至少有一个更好，就说“A 支配 B”，B 可被淘汰。把所有互不支配的方案挑出来，
得到\textbf{Pareto 前沿}（图~\ref{fig:concept}a）。它不是一个点，而是一条
\textbf{取舍曲线}：曲线上的每个方案都是某个侧重下的最优。

\noindent\textbf{在本文中：}算法的输出不是“一个排产方案”，而是这样一条前沿；
因而“算法好不好”也必须用前沿之间的比较来回答，这是 HV 存在的理由。

\subsection{用一个数评价一条前沿：超体积 HV}
要比较两个算法，就需要把“一条前沿”压成一个数。常用的量是\textbf{超体积}
（hypervolume, \textbf{HV}）：先选定一个比所有方案都差的\textbf{参考点} ref，
HV 取“前沿与 ref 之间围出的面积”（图~\ref{fig:concept}b）——前沿越靠近原点
（两个目标都更小），面积越大，算法越好。

但 $C_{\max}$ 与 $W$ 的\textbf{量纲与量级都不同}（一个是时间，一个是若干机器时间之和），
直接算面积没有意义，必须先把两个目标\textbf{归一化}到同一尺度。归一化需要为每个
目标指定\textbf{下界 lo 与上界 hi}。\textbf{这组边界怎么取，正是本文的核心方法学议题}
（\S\ref{sec:caliber}）：一种常见取法只在当批实验内部成立，换一批比较对象读数就变。

\noindent\textbf{在本文中：}正文一律采用“由实例数据确定性推出、与比较对象无关”的边界
（\textbf{实例边界口径}），并在 \S\ref{sec:caliber} 量化另一种取法
（\textbf{盒口径}）的后果。

\subsection{MOEA/D：把多目标问题拆成许多单目标问题}
Pareto 前沿上有无穷多个取舍点，想一次全找到很难。\textbf{分解型}算法把它拆开：
预先给定一组\textbf{权重向量}（例如“七成看工期、三成看负载”），每个权重对应一个
加权单目标子问题；子问题各自求解、并与邻居交换信息，合起来铺满整条前沿。
把多个目标合成一个标量的公式有多种，本文复现对象采用的是 Tchebycheff 形式。
MOEA/D\cite{zhang2007moead} 是这一类的代表。另一条主流路线不做分解，
而是按“谁支配谁”给解排序、并保留整层互不支配的解，代表是
NSGA-II\cite{deb2002moead}；本文不比较这两条路线，提到它只是为说明
MOEA/D 在算法谱系中的位置。

权重向量的集中程度由一个参数控制，记为 $T$：$T$ 小则各子问题关注点差异大、
前沿铺得开；$T$ 大则铺得均匀但彼此接近。本文复现的 RMOEA/D\cite{li2022rmoead}
用 \textbf{Q-learning}（一种“记下每次选择的好坏、下次更倾向选好的”的
强化学习方法）在\textbf{两个决策点}上做选择：(i) 每代该用哪个 $T$（该文称
\textbf{Q-PAS}）；(ii) 该用哪种变邻域搜索算子来改进解（该文称 \textbf{RVNS}）。
此外算法还有一个\textbf{精英档案}，用于保存搜索过程中见过的最好前沿。

\noindent\textbf{在本文中：}上述每个“决策点”都是一个可开可关的\textbf{组件}；
本文把它们排成一条阶梯、逐级打开，检查每一级究竟有没有贡献（\S\ref{sec:res}）。
正文把阶梯上的一个配置称为一个\textbf{臂}（arm）——这个词借自老虎机问题：
把每个组件看成一台老虎机，问“拉它到底值不值”。相应地，逐个开关组件、
观察各自贡献的实验叫\textbf{消融实验}（ablation）。

\subsection{本文用到的四个统计工具}
\begin{itemize}\itemsep2pt
  \item \textbf{配对比较}：让两个配置在“同一实例、同一随机种子”下各跑一遍，
        比较它们的\textbf{差}，而不是比较各自的绝对值。共同因素（实例难度、
        本次抽到的模糊时间）在相减时被消掉，剩下的差才可归因于被比较的组件。
        本文的每一组比较都是配对的。
  \item \textbf{Wilcoxon 符号秩检验}：配对差往往不服从正态分布，用不了 $t$ 检验，
        于是改用只看“差的正负与其排名”的非参数检验，得到 $p$ 值。本文把
        “某组件有增益”严格定义为“\textbf{配对检验 $p<\SigLevel$ 且方向为正}”，
        而\emph{不是}“差不是零”——浮点误差会让任何差都不等于零，
        用“非零”当判据会把所有实例都判成有增益（\S\ref{sec:stat}）。
  \item \textbf{Cohen's $d_z$}：效应量，衡量“差相对于其自身波动有多大”。
        $p$ 值只回答“有没有”，$d_z$ 回答“有多大”，二者必须同时报告。
  \item \textbf{置换检验}：当同时考察很多候选量、又从中挑最大者时，
        普通的显著性门槛会失效（“挑最大”这个动作本身就带来偏差）。做法是把
        实例与目标量的对应关系随机打乱很多次，看“乱着也能得到这么大”有多常见。
        本文用它做多重比较的家族校正，也用它检验“某实例还有提升空间”
        这类事后论断是不是噪声（\S\ref{sec:stat}）。
\end{itemize}

\section{问题、算法与指标}\label{sec:prob}
%======================================================================

\subsection{双目标模糊 FJSP}
给定 $n$ 个工件、$m$ 台机器，每个工件的每道工序的加工时间用三角模糊数
$\tilde t=(t_1,t_2,t_3)$ 表示，且可在其可行机器集合中任选一台加工。目标是
\begin{equation}
  \min \; F = \bigl( f_1 = C_{\max},\; f_2 = W \bigr),
\end{equation}
其中 $C_{\max}$ 为最大完工时间，$W$ 为机器总负载。三角模糊数的比较与
“模糊$\to$确定”（crisp，即把模糊数折算成一个可直接比较的确定值）的规则
沿用 Li 等\cite{li2022rmoead} 的约定，以保证与本项目复现对象一致；模糊区间由
实例名与随机种子共同决定，因此同一实例在不同 seed 下的模糊时间不同，这使
“同 seed 配对”成为一切组间比较的基本单位。

\subsection{超体积（HV）}
本文的单一汇总指标是前沿的 HV（几何含义见 \S\ref{sec:prelim}），
参考点固定为 $\mathrm{ref}=(\SetRefLo,\SetRefLo)$。
HV 的\textbf{归一化边界}取法有两种，本文的全部结论都建立在第二种之上
（\S\ref{sec:caliber}）：
\begin{itemize}\itemsep1pt
  \item \textbf{实例边界口径}（本文采用）：边界 $(\mathrm{lo},\mathrm{hi})$ 由
        实例数据确定性推出（下界取临界路径下界、上界取全部工序最长时间之和），
        \textbf{与参与比较的臂集无关}。实现见 \texttt{instance\_hv\_bounds()}，
        算法落盘的 \texttt{final\_hv} 用的就是它。
  \item \textbf{盒口径}（仅作对照）：边界取参与比较的\textbf{前沿的极值}，
        实现见 \texttt{estimate\_hv\_bounds()}。
\end{itemize}

\subsection{RMOEA/D 的可插拔组件}
复现中我们把算法拆成六个臂（表~\ref{tab:ladder} 的“阶梯”列），每一级相对上一级
只打开一个组件：
$D_1$ 为纯 MOEA/D（固定 $T=10$，关闭 MIX3/RVNS/Q-PAS/精英档案）；
$D_2$ 打开 MIX3 初始化；$D_3$ 打开随机 VNS；$D_4$ 把固定的 $T$ 换成 Q-PAS；
$D_5$ 打开精英档案；\textsf{RMOEAD} 把随机 VNS 换成 RL 选算子。
这一阶梯与文献\cite{li2022rmoead} 表 5 的步骤分解对齐，因而“每一级是否有效”
就是对该文主张的逐条检验。\textsf{RMOEAD} 与 $D_5$ 只差“谁选算子”，
是检验 RL 组件\textbf{最干净的单变量对照}（等算力、同其它一切）。

\section{评价口径：一个会改变结论的隐藏变量}\label{sec:caliber}
%======================================================================
本节是全篇的方法学核心，用一句话概括它的主张：
\emph{同一份实验结果，只要换一种“把多目标压成单一指标”的做法，
就能读出不同的效应量、不同的显著性、甚至不同形状的结论}。
图~\ref{fig:caliber} 用同一批前沿点配两种边界把这件事讲清楚：

\begin{figure}[t]
  \centering
  \includegraphics[width=0.94\linewidth]{fig_caliber.pdf}
  \caption{\textbf{评价口径示意图——点为手工构造，\emph{非实验结果}，不参与本文任何结论。}
  两栏用的是\textbf{同一批前沿点}（红圆与蓝方分别代表两个臂的前沿），
  唯一的差别是“灰框怎么定”。(a) \textbf{实例边界口径}：框由实例数据推出
  （下界取临界路径下界、上界取全部工序最长时间之和），换一批算法来比，框也不会变，
  因此读数可以跨实验引用。(b) \textbf{盒口径}：框取“参与比较的臂的前沿极值”，
  于是框恰好贴着数据——再放进一个更差的臂（灰圈），框的上界就被撑高（蓝虚线），
  同一批点的归一化坐标随之改变。两栏横轴均为完工时间 $f_1$、
  纵轴均为机器总负载 $f_2$，都是未归一化的原始单位，越靠左下越好。}
  \label{fig:caliber}
\end{figure}

下面先说明两种边界取法的区别（\S\ref{sec:boxdef}），再量化后果（\S\ref{sec:boxeffect}），
最后给出本文遵守的报数规则。

\subsection{盒口径的两个缺陷}\label{sec:boxdef}
\textbf{(a) 跨实例污染。} 若把多个实例的前沿并进同一个盒，这个盒就不得不同时容纳
规模相差悬殊的实例。先看一个不需要任何优化知识的量：\textbf{负载下界}——
把该实例全部工序都取最短加工时间再加起来，就是机器总负载 $W$ 再优化也到不了的
理论最小值。在开发集内，仅这一项，最大与最小就相差
$\BndWlSpan\times$（Mk08 的 $\BndMaxLoWl$ 对 Mk02 的 $\BndMinLoWl$），
最大完工时间的下界也相差 $\BndMsSpan\times$。规模差这么远的前沿被塞进同一个框后，
两头的读数都被“拉”进相近区间，于是读出“所有变体都近乎完美”的假象。
凡按 $(\text{臂},\text{seed})$ 在多个实例上摊平再取极值的写法都会踩这一点。

\textbf{(b) 臂集污染。} 盒只应包含\textbf{参与比较的臂}。若把与本次比较无关的臂
一并放进盒（例如把另做的一批 $T$ 扫描臂混进消融实验的日志），上界被无关数据撑高，
同一份数据的所有读数随之改变。本文的对照实验因此\textbf{逐臂对}重算边界，
即盒内恰好只有被比较的两个臂。

\subsection{量化的后果}\label{sec:boxeffect}
表~\ref{tab:ladder} 右三列给出同一批数据（8 臂 $\times$ \DevN\ 实例 $\times$ \SetSeeds\ seeds）
在两种口径下的读数。三点值得注意：

\begin{enumerate}\itemsep4pt
  \item \textbf{放大倍数不是常数}。如果两种口径之间只差一个固定倍数，那么把盒口径
        的数字除以该倍数即可折回实例边界口径，问题尚不算棘手。事实并非如此：按臂对汇总
        （含义是“先各自求均值、再作比”，见 \S\ref{sec:stat}），放大倍数从
        $\CalibAmpLo\times$ 到 $\CalibAmpHi\times$ 不等，逐格子最高达
        $\CalibAmpMax\times$（Mk10 的 $D_4|D_3$：实例边界 $\CalMkTenQpasInst\%$
        $\to$ 盒口径 $\CalMkTenQpasBox\%$）。因此“盒口径数字除以固定倍数即可折回”是错的。

        \emph{那么被放得最狠的是哪些格子？}图~\ref{fig:ladder} 把两种口径并排画出：
        $D_2|D_1$ 的相对增幅被放大 $\CalibAmpMix\times$，而几乎为零的 $D_4|D_3$
        被放大 $\CalibAmpQpas\times$——\textbf{越接近零的效应，相对放大越厉害}。
        在全部 $\CalibCells$ 个（实例，臂对）格子里，
        $|\Delta \hv|\le \CalibSmallThr\%$（“接近零”的显式阈值）的 $\CalibSmallN$ 个
        格子放大中位数为 $\CalibSmallMed\times$，其余 $\CalibRestN$ 个只有
        $\CalibRestMed\times$。\textbf{这里的秩相关必须写明“取了对数”这一步}：
        秩相关的意思是“不比数值大小、只比名次”。先把放大倍数取 $\log_{10}$
        再排名次，得 $\mathrm{Spearman}=\CalibRhoLog$
        （$p=\CalibRhoLogP$）；若直接对原始放大倍数排名次则只有 $\CalibRhoRaw$
        （$p=\CalibRhoRawP$，未过线）。两者方向一致、强弱不同——
        不写出这一步，读者无法复核这个数。这正是“\textbf{任何数字离开其口径
        不可引用}”的一个具体例子。
  \item \textbf{$p$ 值与胜出场数也会变}。这一点比幅度更容易被忽略：口径改变
        不只是“数字大小”，而是\textbf{显著性判定本身}。
  \item \textbf{现象的形状会变}。本文 \S\ref{sec:twoTargets} 会遇到一个
        “3/10 实例显著、7/10 与 0 不可区分”的双峰形态；在盒口径下，那 7 个
        非显著实例变成从 $\BoxNoSigLo\%$ 散到 $\BoxNoSigHi\%$ 的一团
        （中位 $\BoxNoSigMed\%$，且其中 $\BoxNoSigFlipN$ 个\textbf{翻转了符号}），
        于是被读成“效应弱但普遍存在”。\textbf{形状的失真比幅度的失真更难察觉}。
\end{enumerate}

\subsection{报数规则}
本文后续一律遵守：\textbf{效应量与显著性只报实例边界口径}；对照展示盒口径时必须
同时给出放大倍数；任何数字离开其口径不可引用；跨实例只比\textbf{相对差与秩}，
不比 HV 绝对值（各实例边界不同）。

\subsection{参数与算力}
算法本质上是随机搜索：一个\textbf{随机种子}（seed）决定它内部的所有随机选择，
换一个种子就是一次独立重复。单次重复的结果可能碰巧偏好或偏坏，因此每个配置
都要跑多个种子。本文取种群规模 $N_p=\SetNp$（“种群”就是算法同时维护的那一组
候选解，上文的每个权重向量各占一个）、代数 $G=\SetG$（迭代多少轮）、
每个配置 \SetSeeds\ 个随机种子（编号 \SeedRange），$\mathrm{ref}=(\SetRefLo,\SetRefLo)$。
所有组间比较都做\textbf{同 seed 配对}，
以消掉“模糊时间随 seed 变”带来的实例内噪声。响应面实验（\S\ref{sec:surface}）
另在 $G=\SetGMax$ 上限下按\textbf{墙钟预算}分档。“墙钟”（wall-clock）指真实流逝的时间，
它和“跑了多少代”不是一回事：同样的代数，不同配置实际花掉的时间并不相同。
要比较“给更多算力有没有用”，按真实耗时来分档才公平，所以响应面用墙钟而不用代数，
用于观察“算力变大时效应如何变”。

\subsection{统计口径}\label{sec:stat}
同一组比较给两套读数：\textbf{实例级}（先在实例内对 \SetSeeds 个 seed 取均值，
$n=\DevN$ 或 $n=\HKn$）与 \textbf{run 级}（逐 seed 配对，$n=\RunN$）。检验用
Wilcoxon 符号秩（\S\ref{sec:prelim}），效应量用配对 Cohen's $d_z$；
两者的分工是“$p$ 回答有没有、$d_z$ 回答有多大”，本文两者同时报告。

\textbf{相对增幅一律“先求均值、再作比”}，即写成
$\overline{\Delta \hv}/\overline{\hv}_{\text{上一级}}$，而不写
$\overline{\Delta/\hv}$——后者在效应$\approx 0$ 时，分子分母会因正负相消而反号。
\textbf{盒口径的放大倍数也守同一约定}：
$\overline{\Delta \hv}_{\text{盒}}/\overline{\Delta \hv}_{\text{实例}}$，
而不是逐 run 放大倍数的平均，两者相差可达数倍。

存在多个候选预测变量时，一律用\textbf{置换零假设}（固定预测变量的秩矩阵、
只打乱实例与目标的对应）做家族校正，不用 Bonferroni。理由是它回答的问题
更对得上：本文要防的是“\emph{从 $\CalibFamN$ 个候选里挑最大}”这个动作本身
带来的偏差，而置换零假设正是直接模拟这个动作——即使预测变量与目标毫无关联，
纯噪声的 $\max|\rho|$ 在 $n=\DevN$ 下也有 $95\%$ 的机会达到 $\CalibFamNullPct$。
（Bonferroni 只把 $p$ 门槛收到 $\BonfThr$，它假定各候选相互独立；
而本文的候选都是同一批前沿的不同摘要、彼此高度相关。两者的口径并不相同，
本文不做换算。）

\subsection{同一批数据上的两个目标量}\label{sec:twoTargets}
先说清两种被比较的起点。任何进化算法都要先造一批初始排产方案（\textbf{初始化}），
再从这里开始搜索；起点好不好对结果影响很大，这正是 \S\ref{sec:ladder} 里
初始化成为最大组件的原因。本文涉及两种：

\begin{itemize}\itemsep2pt
  \item \textbf{MIX3}（复现对象自带的初始化，也是“目标 B”的对照）：把初始种群
        三等分，各用三条规则之一各造三分之一——完全随机；每道工序挑
        \emph{最可能加工时间最短}的机器；每道工序挑\emph{当前负载最轻}的机器。
        注意三条规则都只在“选哪台机器”上做文章，\textbf{工序的先后顺序仍然
        是随机打乱的}。
  \item \textbf{MWR}（本文的候选变体）：把工序的先后顺序也管起来——按
        \emph{剩余工时最多者优先}排列（一种常见的派工启发式，先把长活排上队），
        机器维度则保留随机性。
\end{itemize}

于是“该不该用 MWR”有两种问法，对应两个不同的目标量：拿\textbf{论文自己的
MIX3 初始化}做对照（目标 B），问的是\textbf{净增量}——“在论文已经达到的水平上
还能多赚多少”；拿\textbf{随机初始化}做对照（目标 A），问的是“有个好起点本身值多少”。
两个量在同一批数据上都算得出来，但\textbf{用目标 A 的答案去论证目标 B 是无效的}：
前者可以很大（好起点普遍有价值），后者却可能一点不剩。
表~\ref{tab:targets} 与图~\ref{fig:targets} 同时给出两者。

\begin{itemize}\itemsep2pt
  \item \textbf{目标 A}（$\imwr$ vs.\ $\irand$）：\TgtAPosN/\TgtAN\ 实例为正、\textbf{\TgtASigN\ 个显著}
        （只有 Mk01 与 Mk05 不显著），幅度 \TgtARange。
        这说明“有个好起点”普遍有价值。
  \item \textbf{目标 B}（$\imwr$ vs.\ $\imix$，净增量）：\textbf{只有 \TgtBSigN/\TgtAN\ 显著}，
        幅度 \TgtBSigRange；\textbf{其余 \TgtBNonSigN\ 个与 0 不可区分}（\TgtBNonSigRange，
        全部不显著）。
\end{itemize}

\noindent 因此 MWR 的净增量是\textbf{全有或全无}的：它在少数实例上有值，
在其余实例上毫无增益。把目标 A 的读数当作目标 B 的答案，正是本文要提醒的
第二类错位；它会把“Mk10 上有净增益”错误地推广为“该初始化普遍更好”。

\subsection{零代探针：把事后解释升级为事前判据}\label{sec:probe}
既然净增益是“全有或全无”，一个自然的问题是：\textbf{能不能事前知道某个实例属于哪一类？}
最直接的判别量是“初始化的 makespan/HV 杠杆”，但它通常是事后量
（从末代档案算）。我们提出的探针只调用一次初始种群构造（等价于 $G=0$，
一次搜索都不做），比较两个变体初始前沿 HV 的相对差：
\begin{equation}
  \lam = \frac{\overline{\hv_0}(\imwr) - \overline{\hv_0}(\imix)}
               {\overline{\hv_0}(\imix)} \times \PctBase\%,
\end{equation}
其中 $\overline{\hv_0}$ 为 \SetSeeds\ 个 seed 的初始前沿 HV 均值
（实例边界口径，ref 与正式实验相同）。代价是每实例 $\times$ \SetSeeds\ seeds
约 1.4\,s。

在开发集（Mk01--Mk10）上，净增益为正的 \HKdevPosN 个实例的 $\lam$ 都落在
$[\HKdevPosLamLo\%,\HKdevPosLamHi\%]$ 内，其余七个都低于门限 $\HKthr\%$
（最接近的 Mk09 为 $\HKdevOthLamMax\%$）；取门限 $\lam \ge \HKthr\%$ 即
\textbf{完全分离}：\HKdevPosN/\HKdevPosN 命中、0 误放、0 漏放。
该门限在开发集上标定后\textbf{冻结}，不再按留出集调整。

这里必须把两个相关系数\textbf{分开}报，否则会重犯本文所批评的那类错位。
（下文 $\rho$ 一律指 \textbf{Spearman 秩相关系数}：把 $\lam$ 与净增量各自排名次，
看两个名次同向的程度——$+1$ 表示完全同向，$0$ 表示毫无关系。）
$\lam$ 自身 $\rho=\ProbeRho$（名义 $p=\ProbeRhoP$）；若改取 9 个事前候选的家族最大，
最高者并不是 $\lam$ 而是“初始种群\textbf{平均} makespan 杠杆”，$\rho=\FamRho$、
置换校正 $p=\PermP$。注意家族零假设下 $\max|\rho|$ 的 $95\%$ 分位为 $\NullPct$，
即 \textbf{$\lam$ 自身过不了这道家族校正}（$\ProbeRho<\NullPct$）。
因此我们\textbf{不}以 $\rho$ 的显著性作为门控依据，只以下面的门限分类结果为准；
这也正是必须做独立留出验证的原因。

需要强调的是，事后量“最终 makespan 杠杆”与净增益的相关更高（$\rho=\MsRho$），
但\textbf{用它做门控是循环论证}：要算它必须先把两个臂都跑完。
探针的价值恰恰在于代价只有一次初始种群构造。

$[\HKdevPosLamLo\%,\HKdevPosLamHi\%]$——两个集合的 $\lam$ 分布并不相同，
位置与跨度都对不上，这正是“门限在开发集上冻结、再到留出集检验”要暴露的东西：
门控可靠与否，取决于留出集的 $\lam$ 有多少落在门限的决策边界附近。

\noindent \textbf{这个判对率必须与平凡基线并列看，否则容易读反。}留出集上真正有增益的
实例只有 $\HKgain/\HKn$，所以\textbf{不加判别、一律拒绝}就能得到 $\HKaccRejectAll$
的判对率，\textbf{比门控的 $\HKaccHold$ 还高 $\HKaccLiftAbs$}。门控一共放行了
$\HKpassN$ 个实例，其中只有 $\HKtp$ 个真赚（精确率 $\HKpassPrec$）；而 $\HKgain$ 个
真赚的实例里有 $\HKfn$ 个被拦下（召回 $\HKrecall$）。也就是说，在这个分布上，
探针的判别\textbf{不如不做判别}。

这个负结果要读准两点。\textbf{其一，它不说明 MWR 无效}——净增量是否普遍存在，
由 \S\ref{sec:twoTargets} 的目标 B 回答。它说明的是“\textbf{用一个零代探针事前
判断该不该用它}”这个方案在跨分布时不可靠：门限是在 $n=\DevN$ 的开发集上挑出来的
（在那里它把全部 $\DevN$ 个实例都判对，判对率 $\HKaccDev$），而 Hurink 上 $\lam$
的分布与开发集并不相同，$[\HKlamLo\%,\HKlamHi\%]$ 的跨度远大于开发集正例所在的
$[\HKdevPosLamLo\%,\HKdevPosLamHi\%]$。

\textbf{其二，判对率低有一部分确实来自决策边界}：$\HKnearHalf$ 个实例的 $\lam$
落在门限 $\pm\HKnearBand$ 个百分点内，而 \S\ref{sec:seedvar} 已证明这一带即使
\SetSeeds\ 个 seed 也判不稳。但\textbf{精确率与召回不受这个解释的庇护}：
即使把所有贴边实例都判对，门控放行的实例里也仍只有 $\HKpassPrec$ 真赚。
所以跨分布的可移植性不是靠调门限能补的。

\section{门控需要几个 seed？}\label{sec:seedvar}
%======================================================================

零代探针虽然便宜，但它仍需要 \SetSeeds\ 个 seed。开发集上两类实例的 $\lam$ 只相隔约
$\HKdevGap$ 个百分点（正例最低 $\HKdevPosLamLo\%$，非正例最高 $\HKdevOthLamMax\%$），
因此“少采几个 seed 会不会翻掉判定”必须实测，
否则“廉价门控”的说法是不成立的。

做法是：对每个实例先算出 \SetSeeds\ 个 seed 的逐 seed 值，再对 $n\in\{1,2,3,4\}$
枚举全部 $\binom{\SetSeeds}{n}$ 个子集、对更大的 $n$ 随机抽样 \PermSubsets\ 个子集，
用与正式探针\textbf{完全相同的公式}重算 $\lam$，最后看这样得到的判定
是否与该实例用全部 \SetSeeds\ 个 seed 得到的判定一致。
表~\ref{tab:probe_seeds} 给出结果。

结论是分层的：\textbf{离门限远的实例在 $n=1$ 就已经稳定}，
而\textbf{贴着门限的实例（如 Mk09，$\lam=\PSmkNineLam\%$，只比门限低 $\PSmkNineMargin$ 个百分点）
即使到 $n=\DevN$ 也只有 $\PSmkNineAgreeTen$ 的一致率}。跨实例平均一致率在 $n=1$ 时约
$\PSagreeOne$，看起来很好，但最差实例只有 $\PSagreeMinOne$ ——
这个平均值把两类实例混在一起，掩盖了边界实例的不稳定。
因此正确的用法是：除了门限判定，还要看\textbf{到门限的距离}；
距离小于约 $\PSsdOne$ 个百分点的实例应被标为“不确定”，或加大 seed 预算后再判。

\section{讨论}
%======================================================================

\subsection{为什么两个 RL 组件没有空间}
三条证据互相独立且一致：(1) 阶梯上 Q-PAS 与 RL 选算子均不显著；
(2) 把 $T$ 的\textbf{动作空间}（强化学习术语，指算法可做的选择集合，
这里即“$T$ 的全部候选值”）穷举扫描一遍，其中也包含动作空间之外的更大候选值：
空间内最优与最差的差只有 $\TscanGapPct\%$
（配对检验 $p=\TscanGapP$、效应量 $d=\TscanDz$，胜出 $\TscanWins$），
\TscanNote
故\textbf{动作空间本身的天花板就很低}；
(3) 算力响应面显示 $G=\SetG$ 附近已接近饱和，
把预算放大到 $G=\SetGMax$（即 $\AnytimeTenX\times$ 算力）也只带来
$\AnytimeTenXPct\%$ 的相对增幅。
把三者放在一起，RL 组件失效的解释不是“学习算法不行”，而是
\textbf{它在两个方向上都无事可做}：可选的 $T$ 值彼此差别不大，
而多算一点也没有回报。反之，初始化改变的是搜索的\textbf{起点}，
它的效应不随算力增长而被稀释（图~\ref{fig:surface} 的衰减正是“起点优势
被后续搜索逐步追平”），因此是这里唯一稳健的杠杆。

\subsection{口径问题在复现研究中的普遍性}
“取参与比较的前沿极值”作为归一化边界，在文献与开源实现里都很常见，
它的问题不是“不精确”而是\textbf{不可比}：读数依赖于同批实验的设计。
本文的量化结果是，同一批数据下效应量被放大 $\CalibAmpLo\times$ 至 $\CalibAmpHi\times$
（逐格子最高 $\CalibAmpMax\times$，由 \texttt{caliber\_audit.py} 与
\texttt{paper\_export.py} 两条独立路径算出同一组数），
且倍数不是常数；显著性判定与胜出场数也会变。
更值得警惕的是它改变现象的形状——把“少数实例显著、其余与 0 不可区分”抹成“处处微正”，
后者恰好支持“效应弱但普遍”这个错误结论。
我们建议复现研究把口径写成一条\textbf{可执行的纪律}（本文 \S\ref{sec:caliber}），
并在论文里同时给出对照，让读者能自行折算。

\subsection{对“组件有效性”这类结论的建议}
本文的负面结论并不是“这个算法不好”，而是指出\textbf{在这批基准与这个算力预算下}，
两个学习组件没有可实现空间。要让“某学习组件有效”成为可靠主张，
至少需要：与要回答的问题对齐的对照（目标 B 而非 A）、
等算力的比较、效应量与显著性两套读数、
以及\textbf{在未参与任何调参的实例上复现}。本文的 Mk06 与 Mk08 属于后一类：
它们从未参与初始化变体的调参，却复现了 Mk10 上的净增益方向，
这比“在调参实例上更好”可信得多。

\subsection{局限}
\begin{itemize}\itemsep2pt
  \item 留出集只有 Hurink $e$-data 一个族，而\textbf{它已经把这个门控否掉了}
        （\S\ref{sec:hurink}）。所以这里剩下的未知并不是“会不会失效”，
        而是换一个族（如 $r$/$v$-data）是否同样失效——按本文证据，
        使用时应默认\textbf{跨族不可移植}。
  \item 门限 $\lam\ge\HKthr\%$ 是在 $n=\DevN$ 的开发集上挑出的，且\textbf{没有做跨族校准}——
        \S\ref{sec:hurink} 表明这正是它失效的原因之一。要让这类门控可用，
        \textbf{必须在目标分布上重新标定}（本文不这么做，因为那等于把留出集变成标定集）；
        而 \S\ref{sec:seedvar} 给出的边界不稳定性说明，即便重标定，
        也必须连同“距门限的距离”一并报告。
  \item 本文只报告 HV 单一指标；虽然 HV 是双目标问题的常用汇总，
        但不排除某些组件在特定目标方向上有局部作用。
  \item 响应面实验受墙钟预算上限限制（$G\le \SetGMax$），
        “饱和”的结论限定在该范围内。
\end{itemize}

\section{结论}\label{sec:concl}
%======================================================================

我们在统一、可复现的评价口径下重新审计了 RMOEA/D 的各组件。主要结论是：
在本基准与算力预算下，真正有效的是\textbf{初始化}与\textbf{算力总量}
（且后者很快饱和），两个 RL 组件（Q-PAS 选 $T$、RVNS 选算子）没有可实现空间。
同时我们发现并量化了一个被普遍忽视的评价口径问题——归一化边界的取法会
把效应量放大一个数量级、改变显著性判定、甚至改变现象的形状。

在建设性的一面，我们给出一个零代探针：它以一次初始种群构造的代价，
事前判定“某新实例上初始化的净增益是否会出现”，并在 \HKn\ 个独立实例上
做了预注册的留出验证。\textbf{该门控没有通过}：留出集上的判对率 $\HKaccHold$
低于“一律拒绝”这一平凡基线 $\HKaccRejectAll$，放行实例的精确率仅 $\HKpassPrec$，
召回仅 $\HKrecall$。因此这一条以\textbf{负结果}呈现：\textbf{廉价的事前门控
在这批基准上不可移植}。这类门控在文献中常被视为“顺手可得”的组件，
因此值得被显式证伪。

我们希望本文的方法学部分——口径纪律、目标量对齐、置换零假设、
以及“把结论放到未调参实例上”——对同类复现工作有直接的可操作性。
